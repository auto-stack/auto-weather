# auto-weather 产品需求目标（Spec: weather-app）

> 本文是 auto-weather 的权威需求基线（`docs/specs/`）。计划（`docs/plans/`）是
> 变更契约；本文描述" agreed 的知识"。对标对象：Apple 天气、彩云天气、和风天气、
> Windy、小米天气等常见天气 App 的核心体验。

## 1. 产品定位

AutoOS 伞形下的独立天气应用：一个代码库同时产出 **Web（Vue 轨）** 与
**桌面（VM 轨）**，手机/平板形态以同一前端的响应式分支承载。数据面支持
**真实天气数据**（可插拔 provider），断网/失败时降级为内置演示样本。

## 2. 形态与平台

| 形态 | 现状 | 目标 |
|---|---|---|
| Web（`auto run`，Vue 轨） | 可用；真实数据面暂缺（rust 桩后端，见 `docs/design/weather-v2.md` §3） | 与桌面端功能对齐 |
| 桌面（`auto run -r vm`，VM merged） | **真实数据面**（v0.6-dev slice-1 起） | 主体验面 |
| 手机竖屏 | `layout_mode=="portrait"` 分支保留 | P1 打磨为正式移动端布局 |
| 平板 | 未启动 | P1 自适应布局 |

## 3. 功能需求分层

### G0 已落地基线（v0.6-dev，PLAN 前置工作）

- 10 个内置中国城市的实时天气 + 24 小时预报 + 5 日预报 + AQI（Open-Meteo）。
- 数据源注记（实时 / 演示样本）与失败渐进降级。
- 深色/浅色主题、横/竖布局切换、城市 pill 切换、刷新。
- 验收：`tests/vm_smoke.py` 18/18 实测真实数据（北京 20°C / RH 96% / 风 9 km/h / AQI 74）。

## 4. 非目标（v1 明确不做）

- 账号体系与跨端云同步（本地持久化即可）。
- 服务端推送/通知（应用内展示为准）。
- 商业化地图/出行整合。

## 5. 数据契约总则（所有计划必须遵守）

1. **前端不直连外网**：一切外部 API 经 `src/back/api.at` 代理；provider 切换不前端改码。
2. **密钥不入库**：任何 key/token/私钥经 env 注入；仓库只留占位与说明。
3. **失败降级**：后端契约统一 `ok:false` 语义；前端保留演示样本兜底，UI 注记诚实标注数据来源。
4. **VM 轨优先实证**：桌面（VM merged）是真实数据主面；Vue 轨受 api_gen 转译面限制时的偏差必须登记（见设计文档 §3）。
5. **已知 VM 配方约束**（2026-10-04 实测，详见设计文档 §6）在 back 代码中不得回退违反。

## 6. 里程碑序列

PLAN-001（城市搜索与管理）→ PLAN-002（生活指数+空气详情+城市管理删排序）→
PLAN-003（降水与预警展示）→ PLAN-004（移动/平板布局）→ PLAN-006（设置中心）→
PLAN-007（i18n zh/en 全量切换；P1 全需求收官）→ PLAN-008（交互补全）；
PLAN-005（QWeather provider）并行待外部阻塞解除。
